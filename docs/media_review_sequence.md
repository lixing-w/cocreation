# Reviewed media sequences

The actual spoken conversation is the content authority. Future dialogue and private planner descriptions never enter the prompter, reasoner or fixer. Only the currently applicable rule requirements and actual reference-slot bindings are supplied.

Spoken-turn rewriting receives separate product and requirement inputs. `requested_outputs` gives the frozen request's exact counts and types (one still image, two separate images, one video, two separate videos, or a mixed list), derived from its planned delivery rather than from format prose. Product content/action remains separate from attached settings. Each attached requirement states its treatment, starting point/duration and applicable categories/subjects: for example, request one park image, and from now on use square 1:1 images and landscape 16:9 videos. Background-season requirements use the same structure. Mentioning videos in an image/video format rule does not add a video product. Rule clarifications and resolutions retain the same pending product contract. Both the general verifier and the keep-rule verifier receive these distinct facts and reject changes to product type/count or cancellation of a product when only a setting is withdrawn. Previously mixed planner suffixes are separated only when constructing writer input; historical run files are unchanged.

Observation asset names identify stable categories rather than versions: `teacup`, with `material: porcelain`, instead of `porcelain teacup`. Both text and video observers explicitly request neutral names and normalize them again after extracting structured attributes. Appearance-qualified identity mentions are neutralized in relationship and shot-staging descriptions, while observed properties remain in their attributes and original evidence. Planning performs the same normalization when loading older observations. Shot staging supplies action and camera information; current adopted references and attributes determine appearance, including when resolving a shot-format conflict.

An asset-and-clip rework is one dependent workflow rather than independent candidate outputs. Resolve referents and existing-clip scope before generating replacement assets. A single first-person reasoner plan covers intent, cross-turn rules and causal references for the whole workflow, targeting about 150 words through prompt guidance only. The assistant first acknowledges the request, then presents this shared plan and the image call. Review the asset image before using it for the video edit. The public sequence records the image call, presents its image result, then records the asset critique. It says that the updated asset is ready and the clip rework is next, adds a short transition inside thinking, then records the standalone video call, video result and video critique in that order. It does not run or display a second full generation plan before the video call; the short transition ends its own thinking block before the call. Any requested assembly follows the accepted clip revisions. Independent alternatives continue to use joint turn review; dependent image/video reworks do not.

Single-output review policy `approved-references-context-season-v3` treats the actual generation input references as the user-adopted identity/design baseline. The critic receives those actual images/video sources, the plain current request, applicable rules and verified canvas; the finished generation prompt is omitted. It compares retained identity to the references instead of reinterpreting perceived age from broad labels such as woman/girl. Static handheld describes camera framing and permits normal subject motion and slight handheld movement. Small differences in smile, eye narrowing, sunlight intensity or apparent age are nonblocking. Score 0 means a clear material failure, 1 means minor deviation or uncertainty, and 2 means met. Acceptance requires every criterion/rule to be at least 1; a clear failure scored 0 still rejects. `reference_alignment` replaces `prompt_alignment`. On resume, archived media with old-policy rejections is reviewed again before any regeneration; superseded critiques remain in `critique_history` and their derived repair prompts are discarded.

The prompt reasoner writes a prospective first-person generation plan while receiving the final generation prompt for alignment. Its three ordered paragraphs begin with “Let's analyze what the user is asking for.”, “Now let's look at which cross-turn rules are effective.”, and “Now let's gather visual references for this generation.” It derives choices from the user request and earlier conversation. The rules paragraph discusses the applicable aspect ratio, explicitly explaining the image 1:1 / landscape video 16:9 defaults when the user has not specified one. Reference decisions explain why an edit or established identity requires a source, or why a new identity does not. The structured prose budget is 3072 tokens, targeting about 150 words across all three fields combined through prompt guidance only. Think fields have no schema character caps or runtime word-count gates. Native model thinking remains disabled. The exact executed prompt is retained separately in the audit report for consistency validation, also supplied as reasoner input for alignment, without being cited as the cause of any decision.

`tools/prompt_fixer.py` is an independent text-only repair tool with its own system prompt and JSON schema. It receives the actual conversation, current rules, numbered output scope, reference bindings, failed prompt and reported visual critique. It returns targeted before/after edits with the failure addressed and visible evidence of success. Python checks exact substring matches, rejects overlap and unchanged or punctuation-only repairs, applies the edits, and validates the complete replacement prompt against the backend parser. Missing `references` means an empty list and is valid for source-free generation. The fixer does not invoke the original placeholder prompt writer. Bounded technical retries retain the invalid response and concrete validation feedback.

Independent multiple outputs in one assistant delivery use one shared reasoner invocation covering all requested products, differences, per-output rules and actual references. The reasoner targets about 150 words in total through prompt guidance only. The first call follows the shared analysis; subsequent calls follow only a short transition. Each actual tool call and its media result appear in sequence, and the complete set is critiqued only after all results have appeared. Multiple outputs in one assistant delivery are generated before any of them is reviewed. The materialization scheduler treats the complete delivery as one dependency unit: downstream tasks cannot consume an individually approved alternative before the whole set passes. `tools/turn_media_review.py` receives the complete unchanged user request, every actual generated image/video in numbered order, each output's actual user-adopted reference inputs, its own active rules and measured canvas. Videos, including video references, are native video content blocks. The Qwen service permits up to eight video blocks per request. No English clause parser or request projection is used. A comparison request is evaluated across the separate supplied files, without requiring a collage in each file.

The turn reviewer scores each output and its rules, using the same tolerant 0/1/2 policy. Python derives the whole delivery decision and repair positions from those scores. Only materially failed outputs are sent to the independent fixer and regenerated, then every retained and new output is jointly reviewed again. Three review rounds and at most three generations per output are allowed. Technical review failures retain every generated file, and resume reviews those existing files before doing further generation. Older individual critiques are retained as history. `turn_reviews` in the leader record preserves complete round snapshots, actual generation invocations, changed output IDs and one joint reflection after all newly generated media in that round. No retained output is falsely represented as regenerated. Current error messages include the actual validation failures rather than labeling every failure invalid JSON.

Single-output deliveries retain the existing image/video review interface. Both review interfaces target about 150 words for the complete reflection through prompt guidance only; prose and rule evidence have no schema character caps or runtime word-count gates. Native width and height are measured and mapped to the supported nominal canvas after pixel-grid rounding. Each review keeps structured first-person request, quality and decision prose, joined with stage introductions and numbered rule evidence by Python. All criteria and rules must score at least 1; only a concrete material failure scored 0 blocks acceptance.

`sequence.json` version 3 and `dialogue.md` are the official exports. Thinking contains prospective prose only. Its final sentence states that the assistant has analyzed the user request, cross-turn rules and applicable references and will now make the image/video call. Python then closes `</think>` and emits an independent `type: "tool_call"` segment with literal `<tool_call>` tags and the machine-readable `tool_calls` array. The JSON contains the exact executed name, prompt, ordered references and parameters; no VLM infers this invocation. The actual media result follows the call, then its critique appears in a separate thinking block. Independent multi-output deliveries place one joint critique after all results; between calls, only a short thought states that the previous image/video has been generated and the next generation will follow. Dependent reworks place the asset result before its critique, then the spoken handoff, a brief thought about reworking the clip, the video call, its result and its critique. Tool calls, including deterministic assembly, never appear inside thinking. Rejected reviews retain their original prose and retry sequence. Accepted results use the existing dialogue delivery without an additional critic reply.

Generation records preserve explicit call options plus effective graph settings, including image six-step guidance, video sampler/steps, scheduler, shifts, CFG, frame count, FPS, dimensions and seed. Retries retain their actual distinct seed and prompt. `dialogue.json`, generation plans and raw model responses remain audit artifacts. Completed media is published only after acceptance. Original run code, raw generation/review records and media remain immutable; changed generation code belongs in a separately versioned run. An explicitly requested export-only repair may rebuild `sequence.json` and `dialogue.md` using `scripts/dialogue_generation/repair_sequence_layout.py`, which backs up both exports, preserves the completion status, and verifies that exact calls, media, spoken text and original critiques are unchanged. It never calls models or modifies audit inputs.

Batch execution uses one persistent shared vLLM service through text planning and materialization, with a 16 GiB KV cache. Standalone review can own an on-demand service. Only model processes owned by the current job are stopped. Pure assembly preserves existing clip content even when newer generation-only appearance rules have been introduced. It never writes an H3 prompt or inserts an implicit clip regeneration. Explicit appearance revisions remain separate clip-generation tasks. Only canvas rules apply to assembly. The first public assistant sentence explains that this request only joins existing clips and the new-media season rule does not apply. A separate operation reasoner receives the actual conversation, applicable canvas rules and planned Python call, with no generation prompt. Its prompt also targets about 150 words total across the three planning fields, allowing room for inserted stage introductions, without enforcing response length. Python records the actual `tools.video_editing.concatenate` arguments (ordered source paths, destination and canvas size) or `shutil.copy2` arguments; the exporter places this invocation in a standalone tool-call segment after closing the assembly thinking block.

Live validation also exposed a contradiction in the original Tamsui spoken request: the current version was a child, while an obsolete source description still said adult female. Before the dialogue writer receives first-reference design notes, `current_source_design` removes obsolete age cues from the primary subject while retaining compatible hair/clothing details. The precise current age remains in the supplied current attributes. Original audit descriptions and old run files remain intact. The media reviewer must not hide such a user/prompt mismatch by treating the generation prompt as authority.

Video review uses 8 FPS with a 64-frame limit across the full clip, including endpoints. Both individual and joint critics compare beginning, middle and end, ground temporal rejections in the visible progression and approximate time range, and do not infer a missing action from one opening frame. A hand/forearm close-up does not imply a face or full-body framing requirement. Ambiguous brief reactions, breathing and shake score 1; only a clearly observed material failure scores 0. The visual critic receives no audio. This remains prompt guidance within the approximately 150-word reflection target, without a response-length gate.

Dependent asset/clip reviews retain the complete actual user request and carry an explicit workflow_stage with the parent delivery output IDs/count. Each sequential stage sets the current review output count to one. The updated asset image is checked for the visual change and retained identity, and the later clip is checked for action and camera movement. The same stage scope reaches the independent fixer. Independent alternatives retain the joint-review guard and are never silently split into single-file reviews.

Both individual and joint visual reviews receive the actual visible dialogue and the current exchange, in addition to the latest user message and authoritative current-rule snapshot. A rule-conflict resolution or a request to proceed does not replace the preceding production request. Season labels are interpreted in the adopted setting and actual framing: absence of generic foliage or a seasonal color palette is uncertainty, not proof of a wrong season. No new scenery is required unless the user requested it. Old-policy rejected media are re-reviewed before regeneration; unchanged accepted individual or joint outputs retain adoption when fingerprints and file hashes still match. Historical raw records remain in the previous run when repairs resume from a separately versioned checkpoint.
